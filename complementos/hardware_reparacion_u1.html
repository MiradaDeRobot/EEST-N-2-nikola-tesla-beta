Unidad 3.1: Metodologías de Diagnóstico

Módulo 3: Diagnóstico y Reparación de Hardware

1. El Arte de Solucionar Problemas (Troubleshooting)

El diagnóstico de hardware es una de las habilidades más valiosas de un técnico. No se trata de adivinar, sino de aplicar un proceso lógico y sistemático para aislar la causa de un problema. Una buena metodología te permite descartar componentes, identificar el origen del fallo de manera eficiente y evitar reemplazar piezas que funcionan correctamente.

Los Pasos del Técnico

Un buen diagnóstico sigue un flujo de trabajo claro:

  1. Recopilar Información: Escuchar al usuario y entender los síntomas. ¿Cuándo empezó el problema? ¿Ocurre siempre o de forma intermitente?
  2. Formular una Hipótesis: Basado en los síntomas, desarrollar una teoría sobre la posible causa (ej. "los reinicios aleatorios podrían ser por sobrecalentamiento").
  3. Probar la Hipótesis: Realizar pruebas para confirmar o descartar la teoría (ej. "monitorizar las temperaturas bajo carga").
  4. Resolver y Verificar: Una vez identificada la causa, aplicar la solución (ej. "limpiar el disipador y cambiar la pasta térmica") y verificar que el problema ha desaparecido.

2. El Proceso POST y los Códigos de Error

La primera línea de defensa en el diagnóstico es el POST (Power-On Self-Test). Es una serie de comprobaciones que el BIOS/UEFI de la placa madre realiza cada vez que se enciende la computadora para verificar que el hardware esencial (CPU, RAM, GPU) está presente y funciona mínimamente.

¿Cómo nos informa el POST de un error?

Si el POST detecta un fallo crítico que impide el arranque, lo comunicará de dos maneras principales:

Códigos de Pitidos (Beep Codes)

En placas madre más antiguas o básicas, el sistema emite una secuencia de pitidos a través de un pequeño altavoz (speaker). Cada secuencia corresponde a un error específico. Por ejemplo:

  • 1 pitido corto: Todo OK.
  • 1 pitido largo, 2 cortos: Error de tarjeta gráfica.
  • Pitidos continuos: Error de memoria RAM.

Nota: Las secuencias varían según el fabricante del BIOS (AMI, Award, etc.).

LEDs de Diagnóstico (Debug LEDs)

Las placas madre modernas suelen incluir un conjunto de 4 LEDs (CPU, DRAM, VGA, BOOT). Durante el arranque, cada LED se enciende mientras se comprueba ese componente. Si el sistema se detiene y uno de los LEDs permanece encendido, te indica exactamente qué componente está causando el problema.

3. Uso de Software de Diagnóstico

Cuando la computadora arranca pero presenta inestabilidad o problemas de rendimiento, el siguiente paso es utilizar software especializado para realizar pruebas más profundas.

MemTest86: Pruebas de Memoria RAM

Es la herramienta estándar para diagnosticar fallos en la memoria RAM. Se ejecuta desde un pendrive de arranque (antes de que cargue el sistema operativo) y realiza una serie de pruebas intensivas en los módulos de RAM para detectar errores. Un solo error en MemTest86 es suficiente para confirmar que un módulo de memoria está defectuoso.

CrystalDiskInfo: Salud del Almacenamiento

Este programa lee los datos S.M.A.R.T. (Self-Monitoring, Analysis, and Reporting Technology) de tus SSDs y HDDs. Te proporciona un informe del estado de salud de la unidad ("Bueno", "Riesgo", "Malo"), el número de horas de uso, la temperatura y otros atributos críticos que pueden advertirte de un fallo inminente.

Software de Stress Test (Pruebas de Estrés)

Programas como Prime95 (para CPU) y FurMark (para GPU) llevan estos componentes al 100% de su capacidad de forma sostenida. Son muy útiles para diagnosticar problemas de sobrecalentamiento o inestabilidad en la fuente de alimentación que solo aparecen bajo carga intensa.
